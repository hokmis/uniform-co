# 人資送出發放與倉庫退回

使用者於 2026-10-11 確認人資倉不足發放量即禁止送出，不可由總倉量替代，也不可負庫存。

新單送出在單一交易扣人資倉發放量，建立獨立不可變流水；調庫需求仍為發放量＋增庫量。既有合計預留只保留尚未消耗的增庫量，避免已扣的發放量再次扣可申請量。送出後的兩倉合計須覆蓋其他有效預留及本單增庫預留。

倉庫完成：總倉減實際調庫量，人資倉加同量，增庫量已包含於調庫需求，不另外再加一次。倉庫退回必填原因並驗證來源版本；沖回人資送出扣量、釋放預留、清除未過帳發貨草稿，狀態回 DRAFT（畫面標示退回待修改）。原單號保留。新單送出後須先由倉庫退回才能修改；取消沖回、重送新扣量均為單一交易。未知回應以分頁 sessionStorage 保存原 payload／原鍵，重新整理不另建單據。

庫存待覆核的需求也列入倉庫清單供退回；完成發貨仍只允許 SUBMITTED，不放寬庫存防線。0141 同步覆寫 queue view；0103 的來源定義與產生器 artifact 保持一致。瀏覽器僅可寫基本草稿欄位，不能改 issue posting／策略／退回／版本欄位；每筆原始扣庫 posting 由唯一 reversal 約束保證最多沖回一次。取消僅限原人資或 SYSTEM_ADMIN。

既有 SUBMITTED 單據維持 LEGACY 策略，發貨仍依舊規則扣發放；新送出的 DRAFT 使用 ISSUE_ON_SUBMIT，既有已完成單不回填、不重寫。退回或取消不得碰觸 POSTED 發貨。依固定 item mutex → request → shipment → balances → reservations 鎖序序列化，送出／退回／發貨重試不得重複過帳。

驗收公共邊界：需求預覽、送出／退回／重送／發貨 RPC、唯讀庫存與流水 view。正式驗收在一筆 rollback-only transaction 內建立最小 fixture，確認無 QA 殘留；單獨部署 migration，保留 schema／ledger 對帳限制。
