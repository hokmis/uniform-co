# 以主檔與期初庫存切換，不搬遷舊交易

新系統設定正式上線日，只匯入機構、部門、員工、制服、供應商及兩倉期初庫存；舊紙本、Excel 與 Google Sheet 交易以原檔封存，不轉成新系統流水。逐筆清理舊交易的成本高且資料品質不足以可靠重建兩倉歷史，強行搬遷反而可能污染新庫存帳，因此以已盤點且簽核的期初數量作為可稽核切點。

正式環境以單一 `system_cutover_state` 鎖住此切點：只有 PRE_CUTOVER 可把一個已驗證期初批次、唯一 opening posting、兩倉餘額與 LIVE 狀態在同一交易發布。LIVE 前禁止一般庫存過帳，LIVE 後禁止任何第二次期初發布；修正切換錯誤不得重跑另一批期初，而須依正式更正／盤點流程處理。
