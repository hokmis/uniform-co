# 使用者操作說明

## 1. 使用前準備

本系統是純線上制服作業平台。請使用管理員建立的登入帳號與密碼，並確認瀏覽器可以連線正式網站。系統不支援離線新增、離線暫存或稍後同步。

登入後可見資料與可執行操作由帳號角色和資料範圍決定。同一帳號可以有多個角色；看到資料不代表一定可以修改。如果出現「權限不足」，請勿改用他人帳號，應由系統管理員檢查角色與需求窗口範圍。

## 2. 登入與共用導覽

1. 在登入畫面輸入管理員提供的登入帳號與密碼。
2. 登入後從左側選擇工作區；手機版使用上方「目前工作區」選單。
3. 工作區上方的模組頁籤會切換同一工作區內的任務，不需要向下捲動尋找功能。
4. 搜尋框可用工作區、流程或欄位關鍵字定位模組；按 `/` 可聚焦搜尋，按 `Esc` 關閉浮動面板。
5. 右上角可切換 `AP`、`MX`、`GS`、`MB`、`SH` 五種介面風格；重新整理後仍會保留。
6. `SYSTEM_ADMIN` 可從原作業台左側或上方開啟「系統說明」；原工作區選單會保留，說明顯示在右側，三個文件按鈕可立即切換。
7. 作業完成後使用右上角「登出」，不要只關閉共用電腦的分頁。

## 3. 角色與主要工作

| 角色 | 主要工作 | 不可直接處理 |
| --- | --- | --- |
| 系統管理員 | 帳號、角色、需求窗口範圍、主檔與期初切換 | 角色本身不取代人資、倉庫、採購或執行長的業務權限 |
| 人資 | 員工、需求、補庫、人資倉盤點、退回、更正、換季彙整 | 不可填寫倉庫實際調庫量，不可修改已發貨原單 |
| 倉庫 | 發貨、採購入庫、總倉盤點、倉庫與盤點更正 | 不可修改人資需求量，不可直接改庫存餘額 |
| 採購 | 供應商、MOQ、採購差異、採購決定與採購單 | 不可覆寫執行長核准量 |
| 執行長 | 核准或退回換季送核版本 | 不處理採購 MOQ 調整與庫存過帳 |
| 需求窗口 | 在開放期間登記被授權機構／部門的換季需求 | 不可跨出 scope，不可操作日常發放、庫存或採購 |

## 4. 總覽、組織與商品

帳號、商品、組織、員工、兩倉庫存、營運報表、採購差異原因碼、更正歷史、CEO 待核版本、換季採購決策品項、換季需求登記與待發貨需求共用同一套管理清單操作：

- 「每頁」可切換顯示筆數，底部可直接到第一頁、上一頁、下一頁或最後頁。
- 「緊湊顯示／舒適顯示」只調整列高，不改資料。
- 「欄位顯示」可隱藏暫時不需要的欄位、全部顯示或恢復預設；穩定識別欄與功能欄固定保留。
- 畫面會顯示目前第幾筆到第幾筆。欄位隱藏、每頁筆數與分頁不會改變資料庫，也不會縮小「匯出篩選結果」的完整集合。
- 五種更正模組的「更正歷史」可搜尋更正單號／原因、依草稿／已過帳／已取消篩選、排序並翻頁；「過帳時間」可從欄位顯示開啟。CEO 待核版本與換季採購決策品項也使用同一套欄位顯示、密度與分頁：前者可搜尋活動／revision／snapshot hash，後者可搜尋品號／品名／數量／決策狀態，再按「選取」載入右側工作區。需求窗口的換季需求登記也可搜尋員工／品號／數量／HR 修改狀態、排序及翻頁，按「修改」後在右側工作區回填；待發貨需求可搜尋需求單／日期／草稿狀態，按「選取」後在右側理貨工作區建立草稿，按「恢復草稿」可載入尚未 POST 的明細；這些清單操作是唯讀呈現，真正保存仍由原業務表單與受保護 RPC 處理。

帳號管理的清單可搜尋帳號、名稱、Email 或角色，並依啟用狀態篩選；按「管理」才會進入帳號設定，清單的欄位設定不會直接修改帳號權限。

### 營運總覽

「總覽」顯示目前角色可讀取的工作佇列、進度、快速入口與最近活動。數字來自正式 reporting views；顯示空白或 0 可能代表沒有資料，也可能代表目前角色沒有來源資料的讀取權限。

### 組織主檔

- 使用清單搜尋、篩選及排序機構與部門。
- 新增部門前必須先有機構。
- 代碼建立後作為穩定識別，不要用改名方式把一筆主檔變成另一個實體。
- 已被交易引用的資料使用「停用」而不是刪除；停用資料不再供新流程選用，歷史仍保留。
- 大量資料使用匯入預覽，確認差異與錯誤後再套用。

### 商品管理

- 商品清單支援分類、狀態、搜尋、排序、分頁、編輯與停用。
- 制服品號也是庫存與鼎新 ERP 的穩定品號；同款不同尺寸必須使用不同品號。
- 供應商 MOQ 維護在「供應商＋制服品號」關係，不是商品的單一全域值。
- 日常單筆使用商品表單，大量異動使用匯入／匯出。

## 5. 員工主檔與日常人資需求

### 員工主檔

1. 進入「人資需求 → 員工主檔管理」。
2. 可依工號、姓名、機構、部門或職稱搜尋，並依狀態與機構篩選。
3. 需要查看離職日或備註時，從「欄位顯示」勾選；這兩欄預設隱藏以保持清單精簡。
4. 新增時填寫工號、姓名、機構、部門；職稱、到職日、離職日及備註依實際情況填寫。
5. 工號建立後不可修改。若新增時遇到既有工號，請返回清單載入該員工後編輯。
6. 離職或不再使用的員工請「停用」；系統不刪除需求、發放、退回或稽核歷史。
7. 大量員工使用 CSV 批次預覽與套用；檔案缺少既有員工不會自動刪除或停用。

### 建立制服需求

1. 進入「人資需求 → 需求與發放準備 → 制服需求」。
2. 選擇發放日期，加入員工與制服品號，填寫每位員工的發放量 `F`。
3. 如需補充人資倉，可依品號填寫增庫量 `I`；系統計算調庫需求 `R = F + I`。
4. 確認每個品號沒有超過兩倉合計可申請量後建立草稿並送出。
5. 送出成功只代表建立預留與待發貨工作；倉庫正式 `POST` 前不得先把制服交給員工。
6. 回應逾時或結果未知時，使用畫面保留的批次／操作鍵重試或重新查詢，不要重複開新單。

### 補庫與員工退回

- 補庫不關聯員工，也不建立需求預留；倉庫發貨時才依總倉現有量正式過帳。
- 員工退回必須選擇原發放明細與退回原因；確認可用後才增加人資倉庫存。
- 換尺寸不是改寫原品號：先退回原品號，再以新需求發放新品號。

## 6. 倉庫作業

### 庫存管理

- 庫存只存在「人資倉」與「總倉」，機構與部門不是庫存位置。
- 可依商品分類、庫存狀態或關鍵字篩選，並排序人資倉、總倉、合計、預留與可申請量；不可直接修改餘額。
- 「欄位顯示」可切換有效預留等欄位；摘要與清單數量都只讀取 `v_item_availability`，不建立第二份庫存。
- 期初庫存只能在正式切換前由系統管理員透過耐久匯入發布一次。
- 庫存與流水可依目前授權匯出；匯出行為會留下 metadata 稽核。

### 發貨

1. 在左側「待發貨需求」清單搜尋需求單／日期／草稿狀態，選取要處理的已送出需求。
2. 若清單標示「已有草稿」，按「恢復草稿」載入理貨明細；沒有草稿時在右側輸入發貨單號（可選）並建立理貨草稿。
3. 確認來源版本仍是最新版本，填寫實際調庫量 `T`；低於系統預設值時短發理由必填。
4. 草稿建立者可修改理貨數量；其他帳號載入既有草稿時依 RLS 僅能檢視，需由建立者修改，或在數量已核對完成時依資料庫權限 POST。
5. 理貨與現場核對完成、準備立即交付時才按正式發貨。
6. `POST` 成功後原單與本次實際量鎖定；後續錯誤必須走更正單。

### 盤點與更正

- 人資只能盤人資倉，倉庫只能盤總倉。
- 草稿保存帳面版本；若過帳前庫存版本已變，系統標記 `STALE_COUNT`，必須重新實盤。
- 發貨、入庫、盤點或退回完成後不得直接改原單，請使用對應更正模組與來源明細。

## 7. 採購、入庫與換季

### 換季活動

1. 人資建立活動、季別、開放／截止時間、適用員工與品號範圍。
2. 需求窗口只能在開放期間替授權機構／部門的員工登記需求。
3. 人資彙整後建立不可變送核版本。
4. 執行長依畫面所見 revision 與內容核准，或填寫理由退回。
5. 核准後，採購才依 MOQ 與供貨條件決定最後採購量；差異原因必填且不覆寫核准量。

CEO 審核時可先在「待核版本清單」依活動、revision 或 snapshot hash 搜尋，並依送核時間或 revision 排序；選取版本後，系統會重新載入該版本的需求明細。明細尚未載入或 revision/hash 已變更時，核准／退回按鈕會保持鎖定，需重新查詢後再操作。

需求窗口登記換季需求時，先選擇目前開放的活動；左側「已登記需求」會列出該活動且在本人授權範圍內的既有資料。可用員工編號、姓名、制服品號、數量或「HR 已修改」搜尋，也可點擊欄位標題排序、調整每頁筆數與欄位顯示。按「修改」會將該列載入右側表單；按「清除表單」則切換為新增模式。儲存或更新後清單會立即回填，活動截止或 scope 不符時仍由資料庫 RPC 拒絕操作。

### 採購與入庫

- 系統管理員在「採購差異原因碼」使用「新增原因碼」建立代碼；從清單按「編輯」可修改名稱或啟用狀態。原因碼建立後不可改名，停用只阻止新流程使用，不刪除歷史。
- 採購可建立採購決定與採購單；取消或短收結案需要理由。
- 採購決策先在「CEO 核准品項」清單搜尋並選取品號；清單中的「待決策／已完成」只反映目前資料狀態，選取後仍須在工作區確認供應商、MOQ、最終採購量與差異原因。已保存的決策不可直接覆寫。
- 倉庫可分批驗收入庫；到貨量必須等於合格量加拒收量，只有合格量增加總倉。
- 超收不可直接入庫，需先由採購在允許範圍內調整訂購量或採購上限。
- 已過帳入庫錯誤使用採購入庫更正，不回頭改寫原紀錄。

## 8. 報表、PDF、ERP 與耐久匯入

### 營運報表

報表顯示中文欄名，支援說明、搜尋、排序、欄位顯示、舒適／緊湊密度、完整分頁與重新整理。資料直接讀取 security-invoker views 並沿用底層 RLS，不會建立第二份庫存或採購數字。

### 正式文件與鼎新 ERP

- 正式 PDF 與 ERP 是背景 artifact 流程；提出請求後可能需要等待 worker 完成。
- 只有正式來源、正確角色及 READY revision 才可下載。
- 鼎新目前的 `UNIFORM-ERP-SALES-v0` 只供內部 smoke；公司正式格式必須以鼎新成功匯入樣本驗收。

### 耐久匯入

1. 選擇正確匯入類型與 CSV／XLSX。
2. 瀏覽器把檔案直傳 private Storage，不經 Vercel request。
3. Worker 核對 MIME、大小與 SHA-256 後才解析與驗證。
4. 處理所有錯誤並確認差異後再 APPLY。
5. 批次進行中不可任意切換匯入類型；可重新查詢、重試目前批次，或填理由取消。
6. `OPENING_BALANCE` 就是期初庫存，只能在 PRE_CUTOVER 由系統管理員發布一次。

## 9. 常見訊息與處理

| 情況 | 建議處理 |
| --- | --- |
| 權限不足或清單為空 | 確認登入帳號、業務角色與需求窗口 scope；不要以共用帳號繞過 |
| 結果未知或連線中斷 | 使用同一操作鍵重試或重新查詢，避免重複建立 |
| 來源版本過期 | 重新載入最新來源，重新建立草稿或重新實盤 |
| 數量超過上限／可能負庫存 | 重新確認品號、兩倉量、預留、訂購上限與已入庫量 |
| 匯入有 ERROR | 修正指定列與欄位後重新上傳；不可略過錯誤直接發布 |
| PDF／ERP 長時間未完成 | 重新查詢 artifact 狀態；由管理員確認 worker、Storage 與 attempt 狀態 |
| 看到停用資料但不能用於新單 | 這是正常保留歷史；需要重新啟用時由有權限角色維護主檔 |

## 10. 安全提醒

- 不要在備註、截圖、工單或 GitHub 中貼密碼、token、service-role key、DB URL 或真實匯入原檔。
- 下載員工、發放、庫存或 ERP 資料後，依公司規定保存與傳遞。
- 不要直接編輯資料庫庫存餘額、append-only 流水或稽核資料。
- 正式作業若與畫面說明不一致，先停止高風險過帳並通知系統管理員查核。
