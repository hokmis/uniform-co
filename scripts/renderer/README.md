# Renderer worker

`renderer-worker.mjs` is a protected job runner for the PDF and ERP artifact RPCs. It must run outside the browser with a database connection whose **same login role** is `job_document_renderer` or `job_erp_renderer`, plus a matching `private.job_actor_bindings` row. It never uses the Supabase service key for database calls.

The renderer adapter is injected through `RENDER_COMMAND` plus optional JSON string-array `RENDER_COMMAND_ARGS`; the command receives `--attempt-id`, `--payload` (a versioned `uniform-document-render-payload-v1` or `uniform-erp-render-payload-v1` JSON DTO), and `--output`, and must write the final PDF or ERP payload to that path. The runner hashes the bytes, sends the upload through the loopback storage proxy, and calls the lease-fenced finalize RPC. A failure creates a retry attempt; an expired lease cannot finalize. `scripts/renderer/adapters/uniform-erp-sales-v0.mjs` is only a deterministic internal smoke adapter, not a validated Dingxin mapping.

Required protected environment for the renderer runner: `DATABASE_URL`, `RENDER_STORAGE_PROXY_URL`, `RENDER_STORAGE_PROXY_TOKEN`, `RENDER_COMMAND`, and optional `RENDER_KIND=PDF|ERP`, `RENDER_OUTPUT_PATH`, `RENDER_LEASE_SECONDS`. The runner never receives a Storage admin key. Deploy `npm run renderer:storage-proxy` separately with `RENDER_STORAGE_PROXY_PORT`, `RENDER_STORAGE_PROXY_TOKEN`, `RENDER_STORAGE_PROXY_DATABASE_URL` using the same-name `job_renderer_storage_proxy` role, `SUPABASE_URL`, and `SUPABASE_STORAGE_ADMIN_KEY`; bind it to loopback/private network only. The proxy checks attempt id, lease token, generation, bucket and exact object key before using the Storage credential. Validate the 0041 generation-specific key smoke before enabling production traffic.

For disposable staging only, `npm run deployment:renderer-smoke` drives the real `renderer-worker.mjs` and `storage-proxy.mjs` with the protected same-name `job_document_renderer`, `job_erp_renderer`, and `job_renderer_storage_proxy` DB LOGINs. It verifies active actor bindings; PDF/ERP claim → payload → proxy upload → finalize; stale lease/generation/object-key fencing; ERP retry-success, terminal failure, and upload-response-loss recovery; historical READY PDF revisions; STOCKTAKE request/download role allow/deny behavior; and Storage-admin byte/SHA-256 verification. `uniform-pdf-smoke-v0.mjs` is a deterministic PDF smoke adapter for this harness only. This active smoke writes synthetic fixtures and append-only evidence and therefore requires the explicit disposable-staging gates documented in `docs/deployment/staging-preflight.md`; it does not replace real Supabase Auth login or browser Storage RLS/signed-URL testing.
